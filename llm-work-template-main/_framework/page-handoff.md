# الگوی تحویل صفحه

تیم مسئول یک نسخه از این الگو را در مستندات خودش تکمیل می‌کند. این فایل الگوی مشترک باقی می‌ماند. موارد نامرتبط را با دلیل مشخص کنید.

| مورد | آنچه تیم مسئول ثبت می‌کند |
| --- | --- |
| شناسایی | شناسه از [فهرست صفحه‌ها](../../docs/page-inventory.md)، نام تیم مسئول، وضعیت و تاریخ تحویل |
| مرجع‌ها | پیوند نیازمندی و طرح، نسخه یا تاریخ طرح و نسخه یا تاریخ [سیستم طراحی](../../docs/design-system.md) |
| تصمیم‌های صفحه | هدف، مخاطب، اقدام اصلی، ترتیب خواندن، محتوای تأییدشده و جریان‌ها؛ با ارجاع به مستند تیم |
| تطابق بصری | اجزای مشترک مورد استفاده و مرجع حالت‌ها؛ مشخص کنید طراحی در عرض باریک، RTL، متن بلند و نبود داده یا تصویر چگونه بازبینی شد. |
| وابستگی | شناسهٔ صفحهٔ مرتبط، تیم مقابل، ورودی یا خروجی مورد توافق و وضعیت تأیید؛ اگر وابستگی وجود ندارد، ثبت کنید. |
| تصمیم باز و استثنا | پرسش یا استثنا، مسئول پیگیری، دلیل، اثر، وضعیت و اینکه مانع پیاده‌سازی هست یا نه |
| نتیجهٔ بازبینی | تأیید تیم صفحه، نتیجهٔ بازبینی مسئول قالب و نتیجهٔ بررسی امکان پیاده‌سازی از فرانت‌اند |

وضعیت تحویل: **پیش‌نویس**، **در بازبینی** یا **آمادهٔ پیاده‌سازی**. جزئیات روند در [راهنمای همکاری تیم‌ها](./README.md) آمده است.
